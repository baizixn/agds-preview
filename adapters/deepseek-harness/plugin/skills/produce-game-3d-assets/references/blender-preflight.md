# Current-process Blender consumer

Engineering owns this mechanism/schema and technical verdict. The authorized executor under the 3D method owns calling it before production. AD owns the brief and visual criteria. This Candidate adapts the earlier ENG-PROTECTION-001 path-role and QA-TEST-001 call-attempt invariants; it does not inherit prior task-root authority.

The only authorized production entry is `scripts/blender_preflight.py`. The exact retained `blender_source.py` is an internal implementation input; its standalone CLI is **not an authorized production entry**. Documentation of the legacy CLI describes its mechanics, not permission to bypass this gate.

The writer is frozen to the exact LF bytes stored in Git and the release: SHA256 `5e05c312c7eff748d0e2ded4a988e9fa9800ecc7c2e906dd99e3e20a4c658270`. The repository's file-specific `.gitattributes` keeps that writer LF on checkout. Verify this raw hash in the packaged and installed copies before handoff; runtime does not normalize line endings, accept alternative hashes, or bypass an integrity failure. This byte binding supersedes the earlier pin of a local working copy with four CRLF endings. It does not inherit that copy's execution evidence; new runtime receipts must identify their actual bytes and process.

Use the latest stable Blender release when practical. The version is recorded for evidence; the fresh process must pass the actual GLB export and import checks. Run a separately authorized fresh Blender process:
```text
blender --background --factory-startup --python-exit-code 1 --python ABS_SKILL/scripts/blender_preflight.py -- --task-root ABS_TASK --requirements ABS_TASK/requirements.json --allow ABS_REPORT_JSON --allow ABS_CANARY_GLB --allow ABS_FACTS_JSON --allow ABS_EXPORT_GLB
```

Requirements schema 2.0.0 has exactly: task_id, mode=rigid_static, source (.blend/.glb), report (.json), canary (.glb), facts (.json), export (.glb), asset_root (exact object name), max_report_age_seconds (positive task-selected freshness window), and schema_version. All paths must be explicit absolute paths strictly within the existing task root. The four allow entries must be those exact output files; directory permits, relative paths, linked/reparse ancestors, missing parents, duplicate/equal/ancestor roles and existing outputs fail closed. Source and requirements are protected inputs. The test fixture contains $TASK placeholders for tests only; production must resolve actual absolute paths.

The consumer probes GLB export/import registration through get_rna_type and contextual poll, then records real call attempts separately. Export failure is condition_failed after an attempt; its uncalled dependent import is blocked, not attempted or passed. The canary is a new tiny GLB, never an asset or proof of art quality. Other versions, FBX, broad render-engine discovery, baking, rigs, animation and lookdev are outside this narrowed route.

The report binds exact task, requirements/source/helper/writer/schema hashes, binary path/hash, Blender version/build, PID and an in-memory process nonce. A subsequent process cannot reuse it. Before invoking the writer in the same process, require return code 0, the closed shipped JSON schema, matching current identity, elapsed monotonic time within the explicit window, completed export/import canaries with matching file bytes, and absent production targets. There is no CLI accepting a previously saved report. Files are ordinary evidence, not signed security credentials; this guard does not sandbox arbitrary Python or an actively malicious filesystem writer.

Report write failure, malformed/duplicate-key JSON, stale or mismatched report, input/config/tool change, unsupported mode, or path failure prevents writer invocation. Recheck paths and identities before report and writer operations. Preserve incomplete canary/export/report files and raw nonzero results. Retry with a new complete set of output paths, never overwrite or silently clean partial results. Source helper failure propagates; an export left on disk is not successful output. The wrapper restores sys.argv even when the callee fails. There are no background listeners, retries, timers, network calls, or persistent Blender preference changes.

Validation in this integration is isolated Python only; fake backends/writers verify orchestration and failure states, not Blender capabilities. Historical exact N0 helper/artifact evidence remains carried_forward_not_rerun. Current Blender, Unity/runtime, device/player, performance, character, complete material/lookdev, rig and animation are not_verified. formal_budget=missing_owner_confirmation; performance_verified=not_verified. Candidate output owner_decision=not_decided.

A changed task, source, requirements, tool, helper, schema, process or allowlist invalidates the report. A changed legacy writer invalidates inherited whole-leaf N0 evidence and is refused until separately reviewed. The reusable method retains bounded rigid/static behavior; downstream Engineering/TA receives formats and raw receipts, independent QA verifies and Reviewer reviews before Owner adoption.
